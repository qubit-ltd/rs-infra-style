# Rust 风格权威标准

本目录是 rs-infra-style 实现、测试和诊断行为的最终参考标准。规则从
reviewing-rust-code-style skill 同步而来；现有检查器、legacy 行为、配置和测试
不得反过来改变规范含义。规则更新需要显式审查并随工具版本发布。

## 规范文件

- [Rust 编码规范](rust-coding-standard.md)：全部 19 条规则及适用范围。
- [Rust 文件头](rust-file-header.md)：版权与许可证的完整七行模板。
- [双语 README 结构](readme-structure.md)：元数据、badge 和末尾章节模板。
- [实现设计](alignment-design.md)：机械门禁的边界、兼容策略和验收要求。

模板细节以对应模板文件为准。例如文件头必须使用完整七行模板，编码规范中的
简化示例不替代模板。

## 机械门禁的边界

门禁只处理能够机械确定的违规，遵循“宁可漏报，不要误报”。

- 只有能够证明规则适用且确实违反规范的情况，才生成阻断性风格诊断。
- 依赖语义、性能证据、业务职责或完整类型解析的判断，交给 skill 人工审查。
- 宏展开、cfg、名称归属、测试层级或文档来源不确定时，不猜测违规。
- 人工审查候选和自动检查盲区不计为风格失败，不改变门禁退出状态。
- 文件读取失败、无效配置、必需工具执行失败等是检查执行错误，应明确报告，
  不能伪装成风格通过，也不能误称为代码违反某条规则。
- 机械门禁通过仅说明已执行的确定性检查未发现违规，不证明全部 19 条规则通过。
- 不为提高规则覆盖率而添加规范之外的硬性限制，不自动生成未经证明的修复。

完整规范涵盖机械检查和人工审查两部分。将完整规则保存在本目录，不代表脚本
必须自动实现每条规则；脚本只实现其中能满足上述精度要求的子项。

当前门禁实现的确定性子项包括：`IMPORT-001` 的 import 形状和分组、
`DOC-001` 的完整文件头、`TEST-003` 的测试文件命名、`TEST-004` 的源码重定向、
`ATTR-003` 的 coverage cfg 与双重例外条件，以及 `ORG-003`、`ORG-001` 的部分
文件布局检查。测试、benchmark、fuzz、example 文件也接受通用文件检查。
`DOC-002`、`DOC-003`、`TEST-001`、`TEST-002`、`BENCH-001`、`FUZZ-001`、
`METHOD-001`、`ATTR-001`、`COMP-001` 和 `README-001` 的语义部分仍由完整
skill 审查；门禁不会用启发式结论替代这些审查。
