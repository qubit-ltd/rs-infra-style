# Rust 日常开发约定

本文件补充编码规范中未覆盖的日常开发判断。源码组织、Rustdoc、测试位置和导入以 [编码规范](rust-coding-standard.md) 为准。当前任务和项目明确约定优先。

- **DEV-001 参数与所有权。** 只读字符串和集合参数优先借用 `&str` 和 `&[T]`。需要接管数据时用签名表达所有权转移。仅在调用方确实需要多种输入形式时引入泛型。
- **DEV-002 错误处理。** 公共 API 优先使用具体错误类型，沿用项目错误抽象。内部错误保留定位所需的操作和对象上下文。项目已使用 `thiserror` 或 `anyhow` 时可继续使用，按需评估新增依赖。生产代码的 `unwrap()` 和 `expect()` 须有可验证的不变量或明确失败语义。
- **DEV-003 类型与生命周期。** 以签名和必要说明表达生命周期，避免用 `'static` 掩盖真实约束。特殊语义使用 newtype，互斥状态优先使用枚举，有合理默认值时实现 `Default`。元组优先解构为具名变量，社区惯用的简短元组可使用数字索引。
- **DEV-004 并发。** 异步上下文避免阻塞 IO，沿用项目运行时。跨线程对象满足所需的 `Send`、`Sync` 约束，明确共享状态和 Stream 的背压、同步与生命周期。
- **DEV-005 测试行为。** 覆盖重要契约的正常、错误、边界与回归场景。用结构化错误或关键上下文断言失败，控制外部网络、时钟及随机状态。性能评估使用 benchmark。新增或移动测试时核对用例被发现并实际执行。
- **DEV-006 验证。** 局部修改先做聚焦验证。需要完整格式、风格或 CI 验证时，先检查项目脚本的作用与调用方式并优先使用。缺少脚本时沿用项目命令，必要时使用 Cargo 工具。报告实际命令、目标、feature 和覆盖范围。
- **DEV-007 署名。** 遵循项目署名约定，实际作者身份应有依据。若确认作者为胡海星，中文写作“胡海星”，英文写作“Haixing Hu”。
